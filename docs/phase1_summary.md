# Phase 1 まとめ：因果推論による適正価格推定エンジン

対象: 渋谷区賃貸物件（Suumo、1〜30ページ分 / 669建物 / 1,711部屋、うちスコア計算対象1,551部屋）

---

## 1. 何を作ったか

Suumoスクレイピング → PostgreSQL → 因果推論モデル → 適正価格・裁定スコア → FastAPI という一連のパイプラインを実装した。

初期モデル（単一重回帰・R²=0.86）との違いは、単に価格を予測するだけでなく「駅徒歩」「階数」が価格に与える**純粋な因果効果**を交絡因子を制御した上で推定し、その効果から算出した適正価格との残差を裁定スコアとして使う点にある。

---

## 2. DAGと識別戦略

想定した因果構造（詳細は `app/analysis/dag.py`）:

- `station_distance → price` の推定を妨げるバックドア: `station_distance ← age → price`（駅近エリアほど再開発で築浅物件が多い）＋ `station_distance ← location_U → price`（未観測の立地プレミアム）
- `floor → price` の推定を妨げるバックドア: `floor ← total_floors → price`（高層ビルにしか高層階は存在しない）

**②階数効果**は建物固定効果（`C(building_id)`）で建物レベルの交絡を丸ごと制御できるため、最もクリーンに推定できる。これが「全部屋スクレイピングが必要」だった理由。

**①駅徒歩効果**は建物を跨いだ比較が必要なため、`age`・`total_floors`・`building_type` を共変量として調整するOLSで推定した。未観測交絡（立地プレミアム `location_U`）が残るため、E-valueで感度分析を行っている。

さらに `address` から町名を抽出した `area_group`（例: `東京都渋谷区笹塚３` → `東京都渋谷区笹塚`）を固定効果として追加した。これは `location_U` の直接観測できない部分を町名単位で近似的に制御するプロキシで、①駅徒歩効果・適正価格モデルの両方で共通に使っている。実際、`area_group` を入れる前は「駅から遠いほど家賃が高い」という符号が逆転した結果が出ており（同じ渋谷区内でも駅距離と地価が単純には比例しないため）、この固定効果を入れたことで符号が理論通りに修正された（詳細は3節）。

---

## 3. 推定結果

### 階数効果（建物固定効果モデル、log-price）

```
log_price ~ floor + np.log(liv_area) + C(floor_plan_cat) + C(building_id)
```

- 係数: **+0.57%/階**（95%CI [+0.40%, +0.74%]、p<0.001）
- R²=0.985、N=1,098部屋（3部屋以上ある206棟）

同一建物内比較のみを使っているため、立地・築年数・構造の交絡が原理的に混入しない。Phase 1で最も信頼できる推定値。

### 駅徒歩効果（共変量調整OLS、building-level、log-price）

```
avg_log_price ~ station_distance + age + total_floors + np.log(avg_liv_area)
               + C(building_type_cat) + C(area_group)
```

- 係数: **-0.27%/分**（95%CI [-0.83%, +0.29%]、p=0.338、not significant）
- E-value = 1.131 → ごく弱い未観測交絡でも効果が消える水準
- N=638棟（`area_group` が抽出できた建物のみ）

`area_group` 固定効果を追加したことで符号が理論通り（駅から遠いほど安い）に修正された。ただし依然として統計的に有意ではなく、E-valueも低いままなので「効果がある」と主張できる段階ではない。渋谷区は駅密度が高く徒歩分のばらつきが小さいため検出力が不足している可能性が高く、次段階ではマッチング法（CEM）への差し替えで検出力向上を狙う。

### 適正価格モデル（log-log ヘドニックモデル）

```
log_price ~ station_distance + floor + np.log(liv_area) + age
           + total_floors + C(area_group) + C(floor_plan_cat) + C(building_type_cat)
```

- R²=0.930、R²adj=0.928、N=1,551

| 変数 | 効果・弾力性 | p値 | 備考 |
|---|---|---|---|
| `np.log(liv_area)` | +1.02% / % | <0.001 | 専有面積の1%拡大に対し家賃が約1.02%上昇（弾力性≈1） |
| `floor` | +1.02% / 階 | <0.001 | 所在階効果 |
| `age` | -0.88% / 年 | <0.001 | 古いほど安い（理論通り）。バグ5修正後の値 |
| `total_floors` | +0.22% / 階 | 0.038 | 建物規模の代理変数 |
| `station_distance` | -0.32% / 分 | 0.056 | 符号は正しく、ほぼ有意（p<0.1） |

適正価格モデルの `floor` 係数（+1.02%）と建物固定効果モデルの結果（+0.57%）は符号・有意性ともに一致するようになったが、大きさは異なる。これは想定内で、**適正価格モデルは予測目的のヘドニックモデル、建物固定効果モデルは因果効果の識別目的**という役割分担になっている。共変量調整だけでは building 間の未観測要因（デザイン性・管理体制など）が `floor` の見かけの効果に混入しうるため、階数の"純粋な因果効果の大きさ"を主張する際は建物固定効果の推定値（+0.57%/階）を使うべき、という結論は維持される。

### 裁定スコア

- 割安（乖離率 < -5%）: 544件 / 割高（> +5%）: 508件（全1,551件中）
- 最も割安な物件: 乖離率 -51.4%

**【考察と課題：残差の大きさと偽陽性（False Positive）リスク】**

全物件の約68%で5%以上の乖離が発生しており、最大の割安率が約50%に達している。`age` 係数の符号バグ（バグ5）を修正した後もこの割合はほぼ変わらなかったため、乖離の主因は age の誤りではなく、OLSの変数に含まれない「日当たり・間取りの構造・設備グレード・リノベーションの有無」などの未観測スペックが残差として表出していることだと考えられる。年数だけでは捉えられない「リノベ済みヴィンテージ物件」と「未改装の築古物件」が同じ `age` 値で異なる価格帯にいる場合、モデルはその差を捉えられず、このままの残差を割安度スコアとして採用すると、設備デメリットを持つ物件を「割安」と誤検知するリスクが高い。

## 4. 見つけて直したバグ（因果推論以前の話）

以下は推定結果に直接影響する構造的バグだった。

### バグ1: 建物IDの名寄せ問題
Suumoの `bc_id` は物理的な建物ではなく「掲載単位」に付与されるため、同じ建物の別部屋が別IDになり、全建物が room_count=1 になっていた。

**対処**: タイトルをNFKC正規化（全角→半角）した上で号室サフィックス（`403号室`等）を除去し、`(title, address)` を名寄せキーとして building を upsert する方式に変更。

### バグ2: th/td 多ペア構造の見落とし
Suumoの詳細テーブルは1つの `<tr>` に th/td ペアが2組入っていることがあり、さらにクラス体系（`property_view_table-title/-body` と `data_01/data_02` 等）がページ内で混在していた。特定クラスへの限定では拾いきれず、`liv_area`・`building_structure` が構造的に欠落していた。

**対処**: `tr` 直下の th/td をクラスに関係なく位置順にzipする汎用ロジックに統一。

### バグ3: 専有面積のバルコニー面積による上書き
`"面積" in key` という緩い条件がバルコニー面積にもマッチし、テーブル内の後の行で処理された方が上書きしていた（`liv_area=3.13` のような明らかに小さすぎる値の原因）。

**対処**: `専有面積` を優先マッチし、一度セットしたら上書きしない（first-match-wins）方式に変更。

### バグ4: 線形モデルの外挿による適正価格の破綻（外挿エラー）
生の `liv_area` を線形投入していた初期モデルでは、100㎡超の大型物件で予測価格が900万円オーバーに膨れ上がる破綻が発生していた。

**対処**: 目的変数を `log(price)` に変更すると同時に、説明変数側も専有面積を対数化する両対数モデル（Log-Log: `np.log(liv_area)`）へ改修。面積の限界効用逓減（弾力性≈1.0）を数式化し、外挿エラーを解消した。

### バグ5: age（築年数）が西暦（建築年）のまま保存されていた
Suumoの築年数フィールドは「築7年」（経過年数）と「2019年3月」（建築年月そのもの）の2つの表記が混在していた。旧実装の正規表現 `(\d+)\s*年` は最初にマッチした数字をそのまま年数として扱っていたため、後者の表記で `age=2019` のような西暦がそのまま保存されていた（DB上774件が該当）。

この結果、適正価格モデルの `age` 係数が **+0.89%/年（古いほど高い）** という直感に反する符号になっていた。これは因果推論上の未観測交絡ではなく単なるデータバグであり、`docs/phase1_summary.md` の旧版では誤って「Phase2で改善すべき未観測交絡」と分類していた。

**対処**: 西暦4桁（19xx/20xx）を先に判定し、該当すれば `現在年 - 建築年` で経過年数に変換するよう `_parse_age()` を修正。既存DBの該当行（age>200を閾値に判定）も `現在年-age` でバックフィルした。修正後、`age` 係数は **-0.88%/年（古いほど安い、p<0.001）** と理論通りの符号に変わった。

### （番外）building_type の取得漏れと一戸建ての除外
`種別`・`構造` はページによって表示の有無が異なるため、建物グループ内の全部屋ページからフィールドをマージして取得率を改善した。また一戸建ては賃料テーブル自体の構造が異なり価格が常にNULLになるため、Phase 0/1のスコープ外として明示的にスキップするようにした。

## 5. 残っている課題（Phase 2以降）

- **駅徒歩効果の非有意性**: `area_group` で符号は修正されたが依然として非有意（E-value=1.13）。マッチング法（CEM）への差し替えで検出力向上を狙う。
- **未観測仕様交絡（築古×リノベ/ヴィンテージ）**: `age` の符号バグ（バグ5）修正後も、年数だけでは「リノベ済みヴィンテージ物件」と「未改装の築古物件」の価格差を説明できない欠落変数バイアスが残る。age の非線形化（age²、age帯カテゴリ化）やリノベ有無のプロキシ変数の追加を Phase 2 の改善対象とする。
- **建物構造情報の欠損**: `building_structure` の取得率が依然として低いため、`age` / `total_floors` によるプロキシ補完で運用中。
- **重複掲載**: 同一物件が別の不動産会社経由で複数回掲載されるケースの名寄せは未対応。
- **Phase 2（予測性能の高度化）**: 非線形・複雑な交互作用を柔軟に学習できる LightGBM などの決定木系モデルを導入し、未観測要因による残差ノイズを抑制する。
- **Phase 2（LLM特徴量）**: OpenAI APIでブランドスコア・立地スコアを生成し、因果モデルの特徴量に追加する。

## 6. 技術スタックと設計判断の要点

- **建物固定効果 vs 共変量調整**: 建物内比較が可能な変数（階数）は固定効果、建物を跨ぐ変数（駅距離）は共変量調整＋感度分析、と使い分けた。
- **地域固定効果によるバイアス修正の実例**: 駅徒歩効果は当初「駅から遠いほど家賃が高い」という逆符号の結果が出ていたが、町名レベルの固定効果（`area_group`）を追加したことで理論通りの符号に修正された。未観測交絡（立地プレミアム）をどう近似的に制御するかという因果推論の典型的な論点を、実データで踏んだ経験。
- **log-linear / log-log の採択**: 価格データおよび専有面積は右に裾が長く、限界効用が逓減する性質を持つため、単なる精度向上テクニックではなくデータ生成過程（DGP）に基づく数式選択を行った。
- **予測用モデルと因果推定用モデルの役割分離**: 同じデータセットであっても、「因果効果の識別（建物固定効果）」と「市場データの価格予測（ヘドニックOLS）」で回帰の目的と解釈の重みづけを分離・提示した。
